# 安全公告与致歉

Uranus iMessage / 小手机 存在登录绕过漏洞，请尽快更新

## 先别慌，花一分钟看这段

我知道看到「安全泄露」这几个字会心慌，所以先把话说在前面。

**这个漏洞不会让别人拿到你的手机号、身份信息，也不会有人冒充你。** 能被读到的是你填在 Uranus 里的东西：API 密钥、Photon 凭据、和角色的聊天记录。

**对方必须先知道你的后台地址才可能访问。** 这不是那种会被病毒全网自动扫描的漏洞。

### 大概率你没事的情况

- 在自己家里的电脑上跑，没开端口转发 → 风险很低
- 用的是有额度上限的中转站 key → 就算被看到，损失也有限
- 从来没把后台地址发给过别人 → 别人得先知道地址才可能访问

### 需要认真处理的情况

- 用的是 VPS / 公网 IP（教程里 `IP:端口号` 那种），端口直接对公网开放
- 用的是小手机版
- API key 是官方直充、余额较多的那种

## 这个风险到底有多现实

我不想轻描淡写，也不想吓唬人，所以把两面都说清楚。

**先说让人安心的那一面。** 想利用这个漏洞，攻击者首先得知道「谁在跑 Uranus」。而 Uranus 用户的分布有几个特点：没有统一域名，大家都是各自的 `某个IP:端口`，散落在全国各地；没有公开的用户名单，谁在用、用在哪，外面查不到；用户规模不大，而且集中在群里这种半封闭的圈子。专业的攻击团伙盯的是那些有几十万、上百万部署的大型系统，Uranus 这个体量在他们的优先级里不高。

**但我必须说清楚另一面：技术上，批量扫描是可行的。** 现在确实有人专门在网上扫各类 AI 服务、寻找泄露的 API 密钥拿去倒卖，这是个成熟的灰色产业，密钥能直接换钱。如果你的后台直接暴露在公网上，理论上是可能被这类扫描扫到的。

**所以准确的说法是**：不是「别人找不到你」，而是「要专门有人来找你」。这是概率问题，不是安全保证。

### 我的建议

- **公网部署的朋友**（VPS、小手机）：请直接按「可能已经泄露」处理，更新完就换掉 key。不要赌概率。
- **本地部署的朋友**：风险确实低很多，但也建议更新。
- **无论哪种**：去模型服务商后台看一眼用量记录。这是最直接的判断依据，有没有被用过，账单上看得最清楚。

换 key 的成本是十分钟，不换的代价可能是账单。这笔账很好算。

### 现在要做的就三件事，十分钟能搞定

1. 更新到最新版（之前怎么更新现在就怎么更新，不会可以问 AI）
2. 照着「怎么自查」那一节看一眼有没有异常
3. 公网部署的，换一次 API key

不用熬夜处理，但今天之内做掉比较好。有任何一步卡住了，群里问我或者直接私聊，我一个一个教。

大家好，我是 Niki。

今天要跟大家说一件我很抱歉的事。Uranus 被发现存在一个**登录绕过漏洞**，在修复之前，任何能访问到你后台地址的人，不需要密码就能读到你的全部配置，包括你填进去的所有 API 密钥、Photon 凭据，以及聊天记录。

## 这个漏洞具体是

Uranus 的控制台（你用浏览器打开的那个界面）和后台之间，靠一组 `/api/` 开头的网址通信。你在界面上每一次操作，改角色、看日志、保存配置的背后都是浏览器自动向这些网址发请求，所以你在地址栏里看不到它们，但它们一直在用。

后台有一道关卡：凡是 `/api/` 开头的请求，都要先检查有没有登录。

问题是这道关卡在比对网址时**区分大小写**，而底层框架**不区分**。于是只要把网址里的字母换成大写，这道关卡就认不出来了，可请求照样会被送到同一个地方，登录检查就这样被绕过去了。

受影响的是全部 146 个后台接口：读配置（含全部密钥）、改配置、读聊天记录、调用各项功能，都不再需要密码。

## 影响范围

- **桌面版 / VPS 版**：v0.7（2026-09-16）～ v1.22.6 全部版本
- **小手机版**：2026-11-18 之前部署的后端

所有人都建议更新，紧迫程度分三档：

| 你的情况 | 风险 | 说明 |
| --- | --- | --- |
| VPS / 用公网 IP 访问 | 最高 | 知道你 IP 和端口的人能直接读走配置 |
| 小手机版 | 最高 | Cloudflare 地址公开可访问 |
| 自己电脑上跑，连公共 WiFi | 中 | 同一个网络下的人能访问你的后台 |
| 自己电脑上跑，家里独立网络 | 较低 | 但仍建议更新 |

**特别说明**：Uranus 的后台默认监听所有网络接口，不是只有本机能连。所以「我只在自己电脑上跑」不等于只有自己能访问，同一个局域网里的其他设备一样连得上。

**关于「有没有被人利用」**：我不想用「暂未发现被利用」来让大家安心，因为这个漏洞被利用是不留痕迹的。读取配置就是一次普通的网页请求，不会产生任何登录失败记录，你那边什么都看不到。没有人反馈，不代表没有发生过。

所以请所有公网部署的用户，都按「可能已经泄露」来处理。

## 来不及更新？先做这一步（30 秒）

如果你现在没时间，**先把后台停掉**，比留着不管安全得多。

**VPS 用户**：

```
sudo systemctl stop uranus
```

角色会暂时下线，等你有空更新完再 `sudo systemctl start uranus` 启回来。

或者，如果你用的是阿里云 / 腾讯云这类，去「安全组规则」里把后台端口改成**只放行你自己的 IP**，外人就进不来了。

**本地跑的用户**：直接关掉程序，或者先断开公共 WiFi。

**小手机用户**：Cloudflare 后台 → Workers → 找到你的 Worker → 临时禁用或删掉。

**停服 = 零风险。** 更新完再开，数据不会丢，一切照旧。

## 怎么修（请照着做）

请务必升级到最新版本。

### 桌面版 / VPS 用户

```
cd /opt/imessage && sudo bash scripts/update-vps.sh
```

路径换成你自己装 Uranus 的那个目录。用一键更新脚本的，更新到 **v1.22.7**。

### 小手机版用户

小手机的后端跑在**你自己的 Cloudflare 账号**里，我这边改了代码也没办法替你修好。请重新部署一次：

```
git pull
npm run deploy
```

控制台网页不用动，这次改的只是后端。

### 公网部署的用户，请额外做这一步

因为无法确认配置是否被读取过，请**轮换一次全部密钥**：

- 各家大模型的 API Key（OpenAI / Claude / Gemini / 中转站等）
- Photon 的 Project Secret
- 填过的邮箱密码、其他第三方凭据

我知道很麻烦，但这是唯一能确保安全的做法。

## 怎么自查（更新完做一遍）

### 第一步：确认漏洞真的补上了

**最容易搞错的一点**：直接在平时用的浏览器里访问，还是能看到配置。这是正常的，因为你在那个浏览器里已经登录了，登录了本来就该看得到。

要验证得**用没登录的状态**：

1. 打开无痕窗口（Chrome / Edge 按 `Ctrl+Shift+N`，手机浏览器找「无痕模式」）
2. 在无痕窗口里访问你的后台地址，把网址里的 `api` 改成大写 `API`

**修好了**：看到 `{"ok":false,...,"needLogin":true}` 这样一串，或者跳转到登录页。

**没修好**：直接看到一大串配置内容，说明更新没生效，往下看「更新没生效怎么办」。

小手机版同理，把地址换成你的 Worker 地址。

### 第二步：查 API 有没有被别人用

这是最实际的损失，去你用的模型服务商后台看**用量记录**：

| 服务 | 去哪看 |
| --- | --- |
| OpenAI 官方 | platform.openai.com → Usage |
| Claude 官方 | console.anthropic.com → Usage |
| Gemini / Google AI Studio | aistudio.google.com → 用量 |
| 各类中转站 | 站点后台的「使用日志」或「额度明细」 |

看三样东西：

- **有没有你不认识的消耗**：比如你昨天根本没用 Uranus，但显示有调用
- **用量有没有突然暴涨**：平时一天几毛钱，突然某天几十块
- **有没有你没用过的模型**：你只用 Gemini，但记录里出现了 GPT-4

**都正常** → 很可能没被用过，但 key 还是建议换掉，对方可能拿了还没用。

**发现异常** → 立刻去服务商后台**删掉那个 key**（不是改密码，是删 key 重新生成）。中转站的话联系站长说明情况，很多站长会帮你处理异常扣费。

### 第三步：查消息有没有被人动过

打开 Uranus 控制台 → 运行日志，往回翻一翻：

- 有没有你没发过的消息被发出去
- 有没有你不认识的时间点突然有活动（比如你睡觉的凌晨三点）
- 角色有没有莫名其妙的回复

也可以直接看手机上的信息 App，和角色的对话里有没有你没印象的内容。

说实话，这一步查到问题的概率很低。能读配置的人通常是冲着 API key 去的，不会费劲去伪造聊天。

### 第四步（可选）：查有没有人访问过

VPS 用户可以看一眼日志：

```
journalctl -u uranus --since "7 days ago" | grep -iE "/API/|/Api/" | head -20
```

**有输出** → 确实有人用大写路径访问过，也可能是你自己刚才测试的。

**没输出** → 没有记录到这类访问。

但要提醒：Uranus 不会记录所有的访问请求，所以**没查到不代表没发生**。这一步只是补充参考，别因为「没查到」就跳过换 key。

## 更新没生效怎么办

如果无痕窗口里还是能看到配置：

```
grep -c "req.path.toLowerCase()" /opt/imessage/server/src/index.js
```

出 `1` 说明代码是新的，出 `0` 说明没拉到。

```
systemctl status uranus | head -3
```

看 Active 那行的时间是不是刚才。不是的话手动重启：

```
sudo systemctl restart uranus
```
